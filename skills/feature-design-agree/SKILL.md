# Agree

Follow the [shared agreement and persistence rules](../../workflows/feature-design.md#shared-agreement-and-persistence-rules). This skill grants no permissions or role changes.

1. Identify the exact proposal ID, choice, and rationale under discussion.
2. Check for explicit confirmation. If ambiguous, ask rather than interpreting interest or a drafting request as acceptance.
3. Apply the shared acceptance rule; record confirmation and rationale in the proposal's agreement history when authorized.
4. Identify affected slices and remaining blocking versus deferred questions.
5. Report which choices are accepted and which artifact updates remain unsaved. Do not imply implementation or handoff readiness from acceptance alone.

For replacements of accepted choices, use [Reconcile](../feature-design-reconcile/SKILL.md).
